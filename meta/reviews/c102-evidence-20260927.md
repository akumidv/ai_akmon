## Owner-accepted decisions (recorded 2026-09-27)

1. **Format: JSON.** Python reads with stdlib `json`, Node with `JSON.parse`;
   `tools/model_routing/registry.json` is the precedent. No TOML for shared data (smol-toml
   only arrives in C103).
2. **Location: next to the reader.** Every data file sits beside the code that reads it;
   every one is in the wheel's file list (automatic — the wheel force-includes the
   directories; verified in the built wheel) and in the corpus snapshot
   (`meta/conformance/corpus.py` `SNAPSHOT_FILES`) and in `meta/self_ci.py::_make_fixture`'s
   file list. C103's single file list carries it to npm.
3. **Finding codes stay literal at emission sites**, so `coverage.py` keeps deriving the
   population from source. Only message text and tables moved. No new dynamic emission site
   was introduced; the coverage gate still derives 125 items from the source.

All three are task-level records (no ADR conflict; D03 already prescribes the data-first
stage) — stated here and in the inventory, not written as ADR blocks.

## Mechanics

- `common/jsondata.py` (new, orchestrator): `read(path)` → `DataFileError` naming the file on
  absence/breakage; `fill(template, values)` for the `{{name}}` placeholder convention
  (code computes every value — formatted numbers, repr-quoted names — before filling).
  One loader per reading module; no import-time I/O, no caches. As first landed every
  accessor re-read its file; the review below bounds the reads (read once at the entry
  point, passed down).
- Loader unit tests: structure pin + loader-path spy + `DataFileError` propagation, per data
  file, in the existing test files (+ `test_jsondata.py`, `test_materialization.py` new).

## Anomalies and resolutions (lanes + integration)

1. **Inventory count deltas (moved verbatim, source is authoritative):** `_PROTOCOL_FAILURES`
   is 21 not 19+1; `read_checks` has 6 not 5 problem templates; `run_checks` 4 not 5
   message/fix pairs; `_CODE_EXTENSIONS` 32 not 33; `render_digest` 11 not 8; `render_report`
   25 not ~15; release finding texts 15 not ~12. Lane C also moved ~7 adjacent texts inside
   the same named functions (the same-vendor unavailability branches, the semantic
   `compute_binding` warning, `no_usable_spec`, `_PLAN_CHECK_QUESTION`, the two `observed`
   fragments, `archive_no_section`) — no new surfaces, all corpus-pinned byte-identical.
2. **C57 checker carve-out** (`meta/checks/runtime.py::own_tool_literals`): a string used as a
   subscript key into a shared data table is a reference, not an ownership of the fact —
   the data file is the owner. Without it the vocabulary move flagged 6
   `runtime.duplicate-query-owner` findings in the two adapters.
3. **`test_cli.py` sys.modules leak:** the hook bench runs hooks in-process; a hook's
   `import common` re-registered fixture-tree `common.*` modules and left them there,
   breaking later loader-spy tests in combined order. Autouse fixture restores the
   repository's `common.*` modules after each test.
4. **`SEVERITIES` (move 10 finish, orchestrator):** `coverage.py` (corpus machinery) imported
   it for the population derivation; it now imports `severities()` — 3-line mechanical
   re-point, the derivation stays source-anchored on the data file the owner is. Lane A
   flagged the call; the owner's decision (c) covers it (severity is a table, not a code).
5. **`nosession` single-owner closure (lane B follow-up, orchestrator):** the two inline
   literals in `hooks/analysis-guard.py` / `hooks/role-on-code.py` now read
   `common.markers.unidentified_identity()`.
6. **Placeholder traps caught pre-landing:** `akmon_hook_markers[2]`
   (`{{cli}}" hook ` — closing quote before `hook`, trailing space load-bearing) and a
   `delegation_ask_message` fragment (lowercase `exploration/summaries →` prefix) — both
   caught by the lanes' old-vs-new byte harnesses before any code edit; zero scenario
   re-records.
7. **Carrier-path loaders (lane D):** `src/akmon` modules resolve `jsondata` at call time via
   `cli._embedded_common_module(_tree.embedded_tree_root(), "jsondata")` (wheel `_tree` vs
   checkout both work); `bin/` loaders resolve `import common` at call time because
   test_cli's embedded-tree re-registration swaps `sys.modules["common"]` mid-process.
8. **Dev-side ripples (allowed, no corpus impact):** canary population +4 (adapters now
   name the neutral tokens; classified owner-visible), `test_record_owner.py` dropped the
   `common/check_runner.py` entry for the `.akmon.toml` literal (now owned by the data
   file), `test_tree_members_match_the_wheel_force_include` reads the data file.
9. **Scratch:** lane D's diff harnesses lived in `.qwen/tmp/c102/` (untracked); removed
   after the work — they had tripped the ruff-profile size check until then.
