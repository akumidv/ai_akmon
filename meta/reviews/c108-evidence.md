# C108 evidence — tools port + `akmon tool`

Task: [C108](../TASKS.md). Plan row: [design §6](../design/node-consumers.md#6-implementation-plan) — every `tools/`
module in `js/tools/` passes the tool corpus; `akmon tool <path>` in Python and JS; messages name the executing
implementation's command; `exports` map with a documented module API. Decision: ADR 0020 D06. ADR 0020 D08 applies:
[`meta/conformance/DIVERGENCES.md`](../conformance/DIVERGENCES.md).

Two passes: **pass 1** the command, the messages, the module API and four tools; **pass 2**
`model_routing/stats` and `release/release_check`, the two largest and the two with outside dependencies (the usage
API; git, the release suite).

- **`akmon tool <path> [args]`** in both CLIs: `<path>` is the tool's path under `tools/` without the suffix
  (`model_routing/init`). The tools are listed in `src/akmon/cli.json` (`tools`), so a library module
  (`model_routing/routing`), a path outside `tools/` or a suffixed name is unknown (exit 2, the available tools named).
  A listed tool the running tree does not carry is unknown too (an older mount; until pass 2, `stats` and
  `release_check` on node). Python resolves the controlling tree as `path` and `hook` do and runs the script as a
  subprocess; JS imports the module and calls its `main(argv)`. `test_cli_tools_list_is_every_runnable_tool` keeps the
  list equal to the `tools/` scripts with an entry point.
- **Messages name the executing implementation's command** (the C101 review debt). One table in `agents.json`
  (`tool_command`), chosen by where the executing tree is:
  - from a mount: `python3 <AITNA_ROOT>/akmon/tools/<path>.py` — a mounted project has no installed CLI;
  - from the wheel: `akmon tool <path>`; from the npm package: `npx akmon tool <path>`.
  It is used in the routing self-check line, the routing init instruction (both were `python3 $(akmon path)/tools/…`,
  which a Node project without Python could not run) and the gate-audit hold (was the bare
  `tools/model_routing/gate_pack.py`). The gate-pack's empty coverage sentinel names the tool, not the file.
- **The generated agent banner** names no file: "Generated by akmon's model_routing/init tool from registry.json — …".
  The banner is also what marks a file as generated for the obsolete sweep, so the earlier text stays recognised
  (`generated_banners_earlier`); unit row `art/obsolete-earlier-banner` on both implementations.
- **Module API:** `package.json` `exports` maps `akmon/tools/<path>` to each ported tool (and `./package.json`).
  Documented in [`tools/README.md`](../../tools/README.md) § JavaScript module API: each module's named exports, all
  with `main(argv)`; public under the release versioning. `model_routing/routing`, the hooks and `common` are not
  exported. Pinned three ways: `test_the_exports_map_is_the_tool_module_api` (the map is derived from the tool list),
  `js/tools/exports.test.mjs` (each specifier resolves through the package's self-reference to the module `akmon tool`
  runs; the rest does not resolve; the README table equals the real exports).
- **Corpus:** normalization v3 — `{{tool <path>}}` is the `akmon tool` / `npx akmon tool` spelling (was
  `python3 $(akmon path)/tools/<path>.py`); the runner maps the `tool` command, and a `tool` scenario on node waits for
  the named tool's port. The routing unit table follows the new parameters (`status_lines`, `init_instruction`,
  `gate_audit_request` take the command) and gains `tool_command`, `generated_banners` and the earlier-banner sweep.
- **Pairing:** four exemptions gone; 40 files, 36 paired, 4 exempt (the two package inits, `stats`, `release_check`); pass 2
  removes the last two.

- **`stats`:** the budget call is the global `fetch` with a 10 s timeout, so the JS `main` is async (`akmon tool`
  already awaits it); unit-tested with a stand-in fetch, the corpus runs `--no-budget`.
- **`release_check`:** `--subject package --check` runs the executing tree's own `verify` (the JS CLI under node) and
  shows the same `== akmon verify …` line. `--subject akmon --check` (also the default) is refused on node before any
  output, exit 2, with one line naming the Python command (`release.json` `run_check.akmon_python_only`, DV30):
  akmon's own suite exists only in its source repository. `--state` and `--plan` are ported for both subjects.
  A stray positional (`--plan v1.2.3 extra`) is refused as argparse refuses it, `unrecognized arguments: extra`,
  exit 2 on stderr (DV12 for the program-name prefix); the JS parser had accepted and ignored it.
- **`akmon tool`:** with every tool ported, the available list is the same on both, so `cli/tool-unknown` pins the
  refusal of a library module on both.
- **Exports:** `akmon/tools/model_routing/stats`, `akmon/tools/release/release_check`, rows in `tools/README.md`.
- **Pairing:** the last two C108 exemptions gone; only the two package inits remain exempt.
- **Divergences:** DV30 (the akmon-subject refusal), DV31 (`stats` budget failure text), DV32 (`stats` float and big
  token counts), DV33 (`release_check` non-ASCII digits); DV16 widened to `release_check`'s spawn and read failures.
- **Not run:** the real usage API from JS (stand-in fetch only); `release_check --subject akmon --check` on Python is
  untouched by this pass.
