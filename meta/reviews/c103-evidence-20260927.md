## Anomalies and resolutions

1. **Four delegation deaths, one full re-do.** C103's lanes were delegated per the standard
   (vendor/pins, carrier files, corpus node side, docs, unit modules); three subagent runs
   died on provider stream caps (one twice) leaving, respectively, everything, half, and
   nothing on disk. The untouched scope (the five stdlib-gap modules, `probe.mjs`, the tsc
   annotation pass) was done by the orchestrator directly; every landed artifact was
   re-verified from disk state, not trusted from a report.
2. **One scenario re-recorded (spec change, reviewed against the predecessor).**
   `cli/init-vendored` pinned `vendored 14 standard-tree members`; js/ is now the 15th member
   (the wheel ships it, so mode vendored must mount it — ADR 0009 §1 equivalence). The re-
   record diff is that one line and nothing else. Zero other scenario files changed; no
   re-record was needed for anything else — the release-carrier rule fires only for the
   `akmon` subject, and every release scenario pins the `package` subject (verified: all 7
   pass against the unedited files). The review round below added three more re-records, for the
   release wording.
3. **A false alarm, then the real mechanics** (M107): an early scan of the freshly built
   wheel appeared to show cache dirs needing an exclude edit — a repro in a scratch project
   proved hatchling's force-include walk filters by its **hardcoded** constants
   (`__pycache__`, `.ruff_cache`, `.pytest_cache`, `.git`, …), never by the project's custom
   `exclude` patterns: the caches never shipped, the added patterns would have been inert
   (reverted, with the mechanics documented in a pyproject comment), and the one genuine
   divergence is the fixture `.gitignore` — excludable by npm (it hard-drops it) but not by
   the wheel. See decision 4 for how the owner's call landed.
4. **smol-toml defaults are the safe ones and were verified, not assumed**: `useLegacyDate:
   true` keeps datetimes as `TomlDate` (JSON-stringify to ISO) with **no Temporal dependence**
   on the Node 22 floor (M104). The adapter normalizes the one mechanical difference the suite
   shows (`17:45:00.000Z` vs the suite's `17:45:00Z` zero-fraction spelling) — non-zero
   fractions are kept, not trimmed.
5. **The npm `node@22` package is unusable here** (npm 12 blocks its preinstall downloader);
   the floor was proven with the official nodejs.org tarball extracted to scratch (M106), and
   the npm `node` binary was never installed globally.
6. **Two units-table properties JS loses at parse time** — integer-like-key order and floatness
   — are restored in `probe.mjs`: the order by a raw-text walk of the `value` expression,
   floatness by a TOML scalar classifier (a fraction, an exponent or an inf/nan word, tested
   *after* the radix prefixes so the hex `0xE` stays the integer it is) feeding the writer's
   `FloatValue` marker. The first pass got both wrong in ways the review round below names: it
   marked floats by `[.eE]` in the written text (which read `0xE` as a float and wrote `14.0`
   for 14) and the writer spelled floats with `toFixed(20)` (which writes the binary expansion:
   `0.1` came out `0.10000000000000000555`). The rule is now `float_repr` ported, exact for
   floats in general rather than for the ones the tables happened to carry.
7. **First-run test bugs found by the suite, in the orchestrator's own tests** — the
   check_runner malformed-entry cases (`files: ["one"]` is a *valid* pattern list;
   `"*.py"` quotes are *balanced*) were replaced with genuinely malformed inputs;
   a `sed`-style bulk fix hit a fourth same-shaped lambda (`_git_tags`) and had to be
   hand-reverted. Both classes were caught before the boundary by running the batteries.
8. **The Finding envelope rejects version literals in `fix` text** (`_SECOND_SENTENCE_RE`
   counts a period before a space or capital as a second sentence — `X.Y.Z`, `package.json`):
   the npm-carrier fix texts name "the npm carrier" instead. The rule is pre-existing and right;
   the new texts were shaped to it.
9. **A C102-era test-isolation fix proved load-bearing**: the `sys.modules["common"]` restore
   fixture in `meta/tests/test_cli.py` keeps the runner's in-process hook bench from poisoning
   the C103 loader-spy tests in combined order (1862 green in one process).
10. **Scratch under `.qwen/tmp/` was not fully removed** — the claim this file used to make
    ("moved to `/tmp/c103-run/` and deleted from the repo at integration") was true of the
    Node 22 and toml-test trees and of most probe scripts, but one probe (`smol_probe.mjs`,
    holding an absolute path to this working copy) stayed in the tree *and was staged*. The
    owner's review caught it in the commit set. It is deleted, and `.qwen/` is now in
    `.gitignore`: the directory is per-session harness state, and being merely untracked was
    enough for `git add` to sweep it in. The eslint config additionally ignores `.venv/**`
    (an installed wheel's copy of the tree must not answer for the source).
11. **`smol-toml` accepts a leading BOM** (verified) where `tomllib` refuses it; the record
    units table pins `strict_ok = false` for the BOM case, so the JS strict reader refuses it
    explicitly before parsing — the table, not the library, is the spec.

## Review round (owner, 2026-09-30)

The owner reviewed the staged set and found twelve defects. Every one is fixed; each fix is
pinned where the standard pins behaviour (a shared units table, a `node:test`, a pytest, the
gate itself), not only in the code. Findings and resolutions:

1. **The staged set was mixed** — a scratch probe (`.qwen/tmp/smol_probe.mjs`) and the A32-E2
   run-status audit were in the index, and this file's item 10 claimed the scratch was gone.
   Unstaged, deleted, and the E2 file returned to its `HEAD` content (its index blob is kept at
   `/tmp/c103-run/a32-e2-backup.md`); `.qwen/` is now ignored rather than merely untracked.
2. **Version comparison compared arrays as strings** — `probe.mjs` ranked order keys with `<`,
   which is Python-tuple semantics read into JS array syntax: `0.10.0` below `0.9.0`, `2.0.0`
   above `10.0.0`. The table was green only because it carried no multi-digit pair. There was no
   comparator in either implementation, so C105 and C107 would have inherited the mistake.
   `compare_versions` / `compareVersions` is now the single owner of the ordering in
   `common/versions.py` and its twin (raising on an unplaceable version), `probe.py` asks it
   instead of using `<`, and `units/versions.toml` carries the multi-digit pairs (with a raise
   spelled `"error"`, TOML having no null). *Found while in the file:* the JS
   `DESCRIBE_SUFFIX_RE` also lacked Python's `$` anchor, so
   `0.4.0-3-g1234abcd-x` split at the first distance instead of staying whole — anchored now,
   and pinned by a new `[[case]]`. No live Python call site was wrong: `_update.py::_plan`
   compares two order keys with `>`, which is right for tuples and wrong for arrays, so it stays
   as it is (C107's port is where it changes, and the twin it changes to is now in the table).
3. **`check_runner.mjs` captured the check's output** — `spawnSync` without `stdio` pipes the
   child and caps the pipe at 1 MiB: the owner never saw the linter's report, and a verbose one
   died as `ENOBUFS`, which the catch-all reported as the command not being installed. The twin's
   contract (`subprocess.run(argv, cwd, check=False)`, no capture) is now matched: `stdio:
   "inherit"`, only `ENOENT` becomes the not-installed finding, any other spawn error propagates, and a
   signal-killed child reports the negative signal (`exited -9`) instead of `exited null`. The
   git call in `changedFiles` keeps its capture (the names are the answer) but got a raised
   `maxBuffer` for the same reason. Pinned by four new `node:test` cases, one of which runs the
   runner in a child process to prove the command's stdout reaches the terminal.
4. **The stub bin did nothing when installed** — npm puts a *symlink* in `node_modules/.bin/`
   (measured, M113), so `import.meta.url === pathToFileURL(argv[1])` never held and `akmon`
   exited 0 in silence. The guard compares `fs.realpathSync` of both sides now, with three
   `node:test` cases run through a real symlink. `probe.mjs`'s own guard had the same shape
   against a snapshot path containing a link; there the outcome is the milder opposite — the
   probe prints nothing and exits 0, so the units scenario turns **red** on its pinned stdout
   instead of quietly green (measured: pre-fix exit 0 with 0 bytes, post-fix exit 0 with the
   32-byte document) — and it dereferences both sides for that reason.
5. **`glob.mjs` was a summary of `fnmatch.translate`, not a port** — `{`, `+` and space were not
   escaped (`a{2}` matched `aa` through the regex quantifier), class bodies were copied verbatim
   (`[\d]` became the digit class, `[z-a]` a `SyntaxError`, `[]a]` an empty class), and `?`
   consumed one UTF-16 *code unit*, so it refused a name that is a single emoji. Rewritten as the
   stdlib's algorithm with JS's escape set and compiled with the `u` flag (M109); 28 new cases in
   `units/glob.toml` pin exactly those shapes.
6. **`shlex.mjs` branched on the quote character instead of carrying the stdlib's states** —
   `'a\'` parses in Python (`["a\\"]`) and raised `No closing quotation` here. Rewritten as the
   `read_token` state machine (`' '`, quote, escape-in-flight, word), which also settles the
   neighbouring shapes: `''` emits one empty word, `"a\"` raises for the missing close while
   `"a\` raises for the missing escaped character. Ten new cases in `units/shlex.toml`.
7. **Float spelling was exact only for the values the tables happened to hold** — `toFixed(20)`
   writes the binary expansion, so `0.1` came out `0.10000000000000000555` and `1e16` and
   `-0.0` came out wrong; and `probe.mjs` marked floatness with `[.eE]` on the written text, so
   the hex `0xE` was a float and 14 was written `14.0`. The writer now ports `float_repr`
   (shortest round-trip digits from `toExponential()`, then the fixed-or-exponential choice and
   the `.0`, M110) and the probe classifies a TOML scalar by its written form after testing the
   radix prefixes. Six new cases in `units/json.toml` carry `0.1`, `5e15`, `1e16`, `1.5e16`,
   `1e-5`, `-0.0`, `0xE`, `1_000`, `0o17`, `0b1011`.
8. **`project_root.mjs` resolved lexically** — `posix.resolve` does not dereference, where the
   twin's `Path.resolve()` does, so a start through a link never reached the root. The fix is not
   `realpathSync(resolve(path))`: a sweep against `common/project_root.py` showed that pair
   collapsing `..` *lexically* — before the link is read — which is a second divergence hiding
   inside the first, and it survived in the relative form of a start path even after the
   dereference landed (`link/..` answered the link's own parent, `link/../../target` escaped the
   tree). `_absolute` is now the stdlib's component walk ported (M114): the longest existing
   prefix goes to `realpathSync.native`, and the components past it — which cannot be links, since
   they are not there — are re-attached with `.` and `..` applied to the resolved prefix, which is
   what `strict=False` means. A symlink loop raises with the stdlib's own message text and no path
   answer. Pinned by an 18-row table asked of both runtimes in absolute *and* relative form
   (60 questions, 0 divergences), plus the loop case.
9. **`readChecks` read a TOML date as a table** — `TomlDate` is an object that enumerates as
   empty, so a date under `[check]` produced `needs_command` (a fix that does not apply) instead
   of the twin's `bad_entry`, and a whole `[check]` that was not a table could be lost silently.
   A plain-object test now gates both levels; pinned by a `node:test` case. **Closed
   end-to-end on 2026-10-03** (the owner asked for the reader probe this residual needed): the
   corpus gained `cli/check-date-config`, which runs `akmon check` over a record holding a date at
   all three rejection sites — an entry (`[check].when`), an unknown key inside a spec table, and
   a `files` list — and pins the three findings, in declaration order, exit 1, `stderr` empty.
   The reader path behind it was measured as a differential: 40 fixture records pushed through
   `read_akmon_toml_strict` → `read_checks` and `readAkmonTomlStrict` → `readChecks`, **38 answering
   byte-identically**; the two that differ are the M111 integer boundary, not the checker (M115).
   A units table cannot carry this family — `strict` is compared by deep equality on the parsed
   value, and one date has no spelling both readers share — which is why the carrier is a scenario,
   and `units/record.toml` now points there from where a searcher would look. The scenario is
   Python-side for now, as `--impl node` runs the unit tables until C105 lands the CLI; the recorded
   texts are the ones the probe showed both readers produce.
10. **The pairing gate credited what it should refuse** — an exemption whose every file is
    already ported stayed green (the list could stop saying what is outstanding), and the
    `cli.mjs` stub counted as a landed C105. A `[[stub]]` list now declares a placeholder
    counterpart, which is not a port (so `src/akmon/cli.py` stays exempt and its own exemption is
    required), and a fully-superseded exemption fails as `pairing.stale`. Gate: **40 population,
    6 paired, 34 exempt, 1 of them stub-covered**. `meta/tests/test_pairing.py` (14 cases) pins
    the gap, both staleness directions, the stub rule, and the live tree.
11. **No gate read the manifest** — the §6 row and this file said the carrier shape was tested;
    it was not, so a `dependencies` block, a `postinstall` or a `^` range would have reached
    `npm install -g akmon` unnoticed. `meta/tests/test_manifest_carrier.py` now asserts: no
