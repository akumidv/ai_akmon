## Python changes (behavior the corpus pins, now language-neutral)

- `common/check_runner.py::changed_files` — `check.scope` names the git command and its exit
  status, or the errno name when git cannot run, instead of Python's exception repr.
- `bin/verify.py` — `pointers.generated-freshness` names `akmon sync`, not `sync.py`;
  `routing.vendor-present` fix reads "Add the <vendor> object"; `routing.selection-policy`
  names the allowed reasoner values in prose, not as a Python tuple.
- `tools/release/release_check.py` — suite commands are shown as the akmon command they stand
  for (`akmon verify …`), never the host interpreter path (`_display`); the line is flushed
  before the child runs.
- **Bug:** `tools/model_routing/second_opinion.py` read the registry from
  `<AITNA_ROOT>/akmon/…` unconditionally, so every second opinion in package mode crashed with
  a traceback. It now resolves the tree like `sync.standard_tree_root`; regression test in
  `test_second_opinion_cli.py`. Found by the native attach.
- **Bug:** `common/record.py::read_akmon_toml` folded a leading BOM into the first key, so a
  record saved by an editor that writes one silently declared no mount. The lenient reader now
  reads `utf-8-sig`; the strict reader still refuses the file. Found by the unit tables.

## Corpus machinery bugs found by the new tests (fixed)

- `--record` of a hook JSON document holding a list of objects wrote sibling tables
  (`items0`, `items1`) — the recorded scenario failed its own output.
- `--record` wrote JSON `null` as bare `null`, not TOML — it now refuses loudly.
- Path tokens were applied in a fixed order, not longest-first as documented.

## Left for the owner / later tasks

- `release_check --subject package` reads its second version literal from
  `src/akmon/__init__.py` **in the consumer project** — akmon's own carrier path — so for a real
  consumer `release.version-literals` can never compare anything. The release scenarios plant
  that file to reach the code. What a consumer's second literal is (if any) is a release-tool
  decision, not a corpus one.
- C108 debt: messages still name tool files — the `gate-audit` hold names
  `tools/model_routing/gate_pack.py`, the generated agent banner names
  `tools/model_routing/init.py`. Both are shared spec now, so C108's `akmon tool` change lands
  in both implementations with the scenarios, as D03 requires.
- `check.config`'s target reads `.akmon.toml [check]` while the record lives at
  `<AITNA_ROOT>/.akmon.toml`; `routing.registry-parse`'s message embeds the absolute registry
  path. Cosmetic; pinned as-is.
