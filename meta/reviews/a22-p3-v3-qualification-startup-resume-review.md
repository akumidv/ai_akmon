# A22 P3 V3 qualification startup resume — Codex GPT-6 review

**Finding:** the approved header-optional A qualification cannot resume by simply invoking `advance`. The first invocation stopped on `account/rateLimits/read` with `401 token_expired`, before `prepared.json`, reservation, or provider dispatch. It nevertheless created the first call's private evidence directory and copied auth home. The append-only ledger contains only its header, so `status` reports 0/128 calls and 667,881 / 5,000,000 observed V3-only Codex tokens.

The sealed runner creates the evidence directory with `exist_ok=False` before the quota check. Its exception recorder starts only after `prepared.json` and the reservation event. A second `advance` therefore selects the same first call from the header-only ledger and fails on the existing directory before it can read fresh credentials or subscription limits. `codex login status` reporting a ChatGPT login is insufficient evidence that quota telemetry works.

The runner reads a separate private `AUTH_SOURCE` at `/tmp/a22-p3-v3-successor-9xViiq/codex-home-run/auth.json`. The main `~/.codex/auth.json` was already valid and has the same sealed account ID. The old source bytes were preserved in a private backup, and that `AUTH_SOURCE` was refreshed from the valid main credential. A read-only RPC on a fresh copy of the refreshed source returned interpretable quota usage of 4% five-hour and 9% weekly; this is not a substitute for the runner's per-call fresh check. The earlier stale-credential diagnostic ran inside the orphan home and may have added local files there, which a reconciliation must inventory. No model call was made by either diagnostic.

This is a pre-dispatch authentication prerequisite failure, not a measured quota-threshold breach, a provider transport failure, or a model retry. The existing proposal explicitly forbids repair or retry for terminal failures, but does not specify reconciliation of a directory left by a failure before reservation. The [startup recovery proposal](../experiments/a22-p3/V3_QUALIFICATION_STARTUP_RECOVERY_PROPOSAL.md) makes that missing decision explicit. Until it is accepted, no qualification call should be dispatched. The old runtime and ledger must remain available for audit; no A map, scorer agreement, or B/C result exists.
