- **The ecosystem.** `<AITNA_ROOT>/.akmon.toml` may name `ecosystem`; absent (or empty, or not a string) means `python`, so
  no Python record changes and the Python `init`/`sync` write nothing new. The JS `sync` serves a record with
  `mount = "package"` and `ecosystem = "node"` and refuses any other (exit 2, the `unsupported_record` text of
  `bin/sync.json`, which names what it found). The JS `init` will write `ecosystem = "node"` (pass 3).
- **Node wiring.** `node "<anchor>/node_modules/akmon/js/hooks/<script>.mjs"`; Codex
  `node "<anchor>/node_modules/akmon/js/hooks/codex-hook.mjs" <advisory>`. The spelling is data in `bin/sync.json`
  (`node_hook_command`, `node_codex_hook_command`); the marker `/node_modules/akmon/js/hooks/` was added in C104.
- **The tree is spelled `node_modules/akmon`, unresolved** (pnpm links it into `.pnpm/akmon@<version>/…`, a path that must never
  be committed). Because it is inside the project root, a standard skill's stub pointer is a relative link, never
  `$(akmon path)/…`. A hoisted layout (the tree outside the root) is spelled absolute and falls back to `akmon path`; not
  verified beyond a symlink simulation.
- **`package.json` pin reader** `packagePinStatus`: `dev` (`devDependencies` names akmon), `runtime` (`dependencies`,
  `optionalDependencies` or `peerDependencies`; the worst wins), `none`, `unreadable`. Exactness of the version is
  `verify`'s (pass 2).
- **Dispatcher.** `sync`, `check`, `path`, `hook`, `version` are real; `init`, `update`, `verify` print the
  `not_ported` text (`src/akmon/cli.json`) with their task and exit 2. `hook <name>` runs the hook in process; static
  imports of `cli.mjs` are only `node:fs`, `node:path`, `node:url` and `jsondata` (a test pins the list), and
  the rest is a dynamic `import()`.
- **Corpus on node.** `runner.py --impl node --area cli` runs `node node_modules/akmon/js/akmon/cli.mjs` in a Node-package
  project that the JS `sync` itself warmed up (replacing C104's Python-synced warmup); a scenario of a command or tool
  whose Python file is still unpaired is *pending* (a skip that names the file; `pairing.is_ported`). The `{{ecosystem}}`
  fixture token lets a shared scenario write the record's `ecosystem` line. The snapshot gained `package.json` and
  stand-ins for `profiles/quant.md` and `profiles/python-stdlib.md` (rows of `units/sync`).
- **Pairing.** The `bin/*` exemption is now `bin/verify.py` only, `common/findings.py` and `src/akmon/cli.py` left the list, and
  the `akmon/cli.mjs` stub is gone: 40 files, 25 paired, 15 exempt, 0 stubs.

### Python behavior changed

- `common/findings.py` `_SECOND_SENTENCE_RE` gained `re.ASCII` (the C103 direction): the one-sentence rule for a finding's
  `fix` no longer fires on `.` followed by U+00A0, U+3000 or U+001F, and now fires on `". \xa0"`.
- The commit guard fix of the pass-2 review (see the C104 evidence) is in the same working tree.
- **Corpus, not product:** the Python runs of the corpus now put the installed-package metadata on `PYTHONPATH`
  (`corpus.python_metadata`). Before, `sync` stamped no pin in the corpus because the snapshot is not installed, while a real
  package-mode project always has one (the output depended on the host: on an interpreter with akmon installed seven
  scenarios failed). Six recorded expectations gained the line `_aitna/.akmon.toml` (`init-package`, `sync-*`); each diff
  was read: that line only. `cli/verify-record-toml-invalid` is now warmed up *before* its broken record and records the
  `pointers.generated-freshness` error the stamp makes of it.

## Pass 2 — the reader: `verify`, `always_loaded`, `codex_hooks`, the runtime declaration (ready for owner review)

### What landed

| Python | JS twin | Tests |
|---|---|---|
| `common/always_loaded.py` | `js/common/always_loaded.mjs` | `units/always_loaded.toml` (188 rows), `always_loaded.test.mjs` |
| `common/codex_hooks.py` | `js/common/codex_hooks.mjs` | `units/codex_hooks.toml` (276 rows), `codex_hooks.test.mjs` (a fake `codex` on a temp `PATH`) |

| `common/runtime.py` `declared_runtimes(ecosystem)` | `js/common/runtime.mjs` `declaredRuntimes(data, ecosystem)` | `units/runtime.toml` (+10 rows), `test_runtime_contract.py` |

- **The Python refusal** (review decision 1, above), in `sync` and `verify`.
- **The JS `verify`** serves Node package mode only and refuses any other record as the JS `sync` does (`unsupported_record`
  of `bin/verify.json`, the `unsupported_found` table of `bin/sync.json` through the exported `unsupportedFound`). The
  dispatcher routes `verify` to it; `init` and `update` still print `not_ported`.
- **Node findings**:
  - `hooks.launcher` replaces the `.venv/bin/akmon` check. Causes are checked in this order:
    1. Yarn Plug'n'Play (`.pnp.cjs` or `.pnp.loader.mjs`) → error, fix `nodeLinker: node-modules`.
    2. A hoisted `node_modules/akmon` in an ancestor directory → error that names the location; fix: install akmon in
       this package's own `devDependencies`.
    3. Missing → error.
    4. Present → ok (a pnpm symlink counts as present).
  - `package.dev-pin` reads `package.json`:
    - `runtime` → error;
    - `none` or `unreadable` → warn;
    - `dev` with an exact version → ok;
    - `dev` with a range, tag, `workspace:`, `file:` or URL → warn that names the value, fix `npm install -D -E akmon@<version>`.

    Exactness is not a code of its own: the coverage gate derives codes from the Python implementation, so a Node-only
    code would leak into the shared scenarios' findings.
  - `layout.standard-path` checks the `js/hooks/*.mjs` files the Node wiring runs (`node_wired_hook_scripts`).
  - Every other check is a straight port with the same codes and texts. The mounted-only checks (`gitignore.akmon-pycache`,
    `changelog.unreleased`, the mount paths) are unreachable on node and are left out.
- **Codex host trust** on node: `defaultRunner` is native (`child_process.spawn`, a timer, the same handshake and cleanup).
  Measured against a fake `codex`: a hang with a 300 ms bound returned in 313 ms; a child ignoring SIGTERM returned in
  2311 ms (the bound plus the 2 s grace) and was dead afterwards.
- **Runtime declaration per ecosystem.** `common/runtime.json` `declared_runtimes` is keyed by `python` (unchanged) and `node`
  (`POSIX shell`, `node`, `git` required on Codex, `claude`/`codex` optional). `meta/checks/runtime.py` joins the Node
  declaration to the commands the JS `sync` emits, read through `node` (no `node` on PATH → one error naming the
  prerequisite).
- **Corpus.**
  - `pairing.toml` lost the `common/always_loaded.py`, `common/codex_hooks.py` and `bin/verify.py` exemptions
    (40 files, 28 paired, 12 exempt).
  - New unit scenarios `units/always_loaded` and `units/codex_hooks`.
  - The node attach fixture gained a CI workflow (`npx akmon sync --check`, `npx akmon verify --strict`).
  - Normalization maps `<root>/node_modules/akmon` to `{{tree}}` on a node native run: the link is the tree the consumer
    runs, and a message naming a tree file (`routing.registry-parse`) then reads the same on both implementations.

### Python behavior changed

- `bin/verify.py`: `re.ASCII` on `_DATE_RE`, `_DELEGATION_DEFAULT_RE`, `_NUMBERED_DR_RE`, `_ROADMAP_CITE_RE`, `_DEV_NAME_RE`, the
  legacy D2 owner anchor (now `_LEGACY_OWNER_ANCHOR_RE`) and the `Unreleased` heading search. Examples:
  - `٢٠٢٦-١٠-١١` in `TASKS.md` is no longer a date, and `é2026-10-11` now is;
  - `ADR 12` is no longer a citation;
  - `delegation is the default` no longer satisfies the anchor.

  17 rows pin this on both sides (`test_verify_text_patterns_are_ascii`, `verify.test.mjs`).
- `common/always_loaded.py`: `re.ASCII` on `_IMPORT_RE`. `x @a.md` is no longer an import; the same holds for U+2028,
  U+3000 and `\x85` beside a token (`test_only_ascii_whitespace_makes_an_import_boundary`, 9 cases).
- `common/runtime.py`: `declared_runtimes` takes the ecosystem (required; an unknown one is a `ValueError`).
- `bin/sync.py`, `bin/verify.py`: the refusal of a non-Python record.
