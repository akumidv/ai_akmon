# C102 inventory — data-first reduction (2026-09-27)

**Status: STOP 1 — candidate list, awaiting owner approval. No code changed.**
Baseline: `main` @ `8fdb3ff`; corpus 131/131 green; coverage gate ok (125 derived items).

## Owner-accepted decisions (recorded 2026-09-27)

- **(a) Format: JSON.** Python reads with stdlib `json`, Node with `JSON.parse`;
  `tools/model_routing/registry.json` is the precedent. No TOML for shared data
  (smol-toml only arrives in C103).
- **(b) Location: next to the reader.** Each data file sits beside the code that reads it
  (`common/`, `hooks/`, `bin/`, `src/akmon/`, `tools/…`), never a central `data/` directory.
  Every new file must be in the wheel's file list (automatic — the wheel force-includes the
  whole directories) **and** in the corpus snapshot (`meta/conformance/corpus.py`
  `SNAPSHOT_FILES`), or native scenarios break. C103's single file list carries it to npm.
- **(c) Finding codes stay literal at emission sites** (`self.ok/warn/error("code", …)`,
  `Finding("sev", "code", …)`), so `meta/conformance/coverage.py` keeps deriving the
  population from source. Only message text and tables move to data. A new dynamic emission
  site is a defect, not a `coverage.toml [dynamic]` entry.

All three are task-level records: none conflicts with ADR 0020 (D03 already prescribes
"logic that can be data moves into data files read by both implementations"; the JSON
precedent and the pairing/file-list mechanics are C103 territory). No ADR-level record is
needed; if the owner disagrees, say so at the STOP 1 boundary.

## Method

Five parallel read-only sweeps (one per area: `src/akmon/`, `bin/`, `common/`, `hooks/`,
`tools/`), each tracing readers, size, corpus pins (grep of `meta/conformance/scenarios/`
and `units/`) and move risk; the orchestrator reconciled the results against the corpus
(ecosystem tags, byte pins) and applied the qualification rule:

> **A candidate qualifies only if moving it reduces what C103–C108 must write.** Logic
> (branching, parsing, computation, I/O mechanics, regexes) stays in code. A candidate whose
> text is corpus-pinned must move byte-identical — the corpus is the diff gate, and **no
> scenario file may change**.

Ecosystem note (D02): `python`-tagged-only surfaces (mounted-mode init/update, the full
Python-carrier verify report) are Python-side text; the JS port writes them once from the
same data file and the porting cost is zero either way, so they move with the rest of their
home file rather than being split out.

## Rejected candidates (keep in code)

| Candidate | Reason |
|---|---|
| All regexes (`verify._LINK_RE` … `sync._FENCED_BLOCK_RE`, `common/findings._LINE_SEPARATOR_ESCAPES`, the codex patch regexes, `_TASK_ID_RE` semantics) | Engine-specific semantics (named backrefs, lookaheads); the JS port writes its own engine's pattern — a shared pattern string is not data that saves a line |
| `common/versions.py` (all of it), `common/record.py` lenient parser, `_skill_frontmatter`, TSV/counter parsing, git helpers, merge/dedupe and I/O mechanics, `compute_binding`/ladder logic, `_display` (release) | Pure logic; the corpus unit tables pin *behavior*, and D03 says behavior is proved, not shared |
| `cli.py::_COMMANDS` | `coverage.py` derives the command population by AST-parsing this literal (decision (c)'s spirit: the population stays source-derived); a 3-line tuple is cheap to mirror and the corpus asserts the JS side's commands |
| `_init.py::MODES`, `::CHECK_CHOICES` | argparse `choices`; the error text is argparse-owned (`stderr_contains`), so moving the data does not neutralize the cross-language parser-text risk |
| `__init__.py::_STATIC_VERSION` | `release_check` pins its *source-literal* equality with `pyproject.toml`; moving it orphans the check (negative candidate) |
| Argparse `help=` strings and usage banners (every area) | Parser-owned text, single occurrence, mechanically consumed |
| Standalone scalars (`codex_hooks` timeouts, `MARKER_MAX_AGE_SECONDS`, `gate_pack` truncation limit, `stats._TAIL_BLOCK_BYTES`, …) | No file is created for a scalar alone; if its home file moves, the value rides along (e.g. `_TASKS_MAX_LINES` in #21) |
| `_init.py::_COPY_IGNORE` (6 patterns) | Consumer is `shutil`'s fnmatch mechanics; the vendored mount is Python-side (D02); the JS port owns its copy filter |
| `_init.py::_cfg_sections` TOML-section pattern, `package_pin_status` classification, `_merge_hook_entries` | Parsing/classification logic over external formats |
| `routing.py` dataclass *types* (`Binding`, `AgentSpec`, …), `HookResult` | The types stay per language; the *instances* (AGENT_SPECS) are the data (moved, #12) |
| `stats.py` transcript-subagent file mechanics, `second_opinion` argv building | I/O and `harness_command` assembly; only the text/templates move |

## Order of moves

risk: unpinned tables first (they prove the loader machinery on the cheapest surfaces),
corpus-pinned multi-line text last, with the two most heavily pinned surfaces (verify,
sync) at the end — by then the loader pattern is proven on ~15 files.

## Observations for the owner (not moves)

1. **Python repr bytes in `shared` spec.** `cli/hook-unknown` and `cli/hook-path-refused`
   pin single-quoted `!r` spelling in `stderr` of `shared` scenarios; the JS port must
   reproduce Python's repr quoting for these two lines (JSON quoting would differ).
   C105's JS CLI either emulates it or these two scenarios split per ecosystem — a corpus
   decision, deferred to C105, flagged here because #20 moves the templates.
2. **argparse bytes in a `shared` scenario.** `cli/init-bad-mode` asserts
   `stderr_contains ["akmon init: error: argument --mode: invalid choice: 'bogus'"]` —
   Python's argparse format, on a `shared` scenario. Schema-sanctioned (parser-owned text),
   but the JS argument parser will not spell it the same; same deferred decision as 1.
3. **`k_*` roster duplication.** The delegate roster text is written twice inside
   `hooks/hook_core.py` (nudge + ask) and restates `routing.py::AGENT_SPECS` facts. #5 and
   #12 make each text single-owned; the *roster itself* (names + tiers) already lives in
   `agents.json` data, so the JS port keeps one source for the names.
4. **`_REASONER_POLICY_VALUES` third copy.** `bin/verify.py` and
   `tools/model_routing/routing.py` each hold the `(orchestrator, highest)` fact with a
   "keep in sync" comment; #12 (routing side) and #21 (verify side) make `agents.json`
   / a routing data fact the single owner — the sync comment retires with the move.
5. **Wheel file list.** Decision (b)'s "in the wheel's file list" is automatic for all 22
   files (directory force-include); the operative checklist item is the
   `SNAPSHOT_FILES` additions (done per move, step 21 needs the snapshot re-point too).
