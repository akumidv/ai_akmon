## 2. Findings (ranked, post-auditor re-ranking)

1. **Background/child-session `ask` enforcement gap (major; C31, D2-10).** Live evidence
   (design §13.2, model-routing.md:914–918): a hook-forced `permissionDecision:"ask"` was
   not enforced in a background session — the delegation nudge's hard rung **and the D5
   commit guard** may be no-ops exactly where sessions run unattended. This audit session
   itself ran inside the gap. Needs foreground repro + a background-posture decision
   (`deny` instead of `ask`?) before hook changes.
2. **verify.py checker drift — every verify-touching CI leg deterministically red
   (major; C26, confirmed live).** `bin/verify.py:416` hardcodes `reasoner == "highest"`
   while the registry legitimately says `"orchestrator"` (dynamic reasoner, ADR 0005/0006);
   `meta/self_ci.py` copies the live registry into its fixture (self_ci.py:91–96) and its
   copy-list omits `tools/model_routing/second_opinion.py`. Result at this tree state:
   meta tests **338 passed**, `verify --strict` **exit 1**, `self_ci.py` **exit 1**. A
   normalized-red gate is the dishonest-contract failure finding 3 warns about, with the
   widest blast radius and the cheapest fix. Root cause generalizes: the checker
   hand-restates registry values, violating the standard's own "derive from the single
   source" guardrail. Fix the checker (not the registry — a worker-tier fix suggestion to
   flip the registry was wrong, a calibration datapoint in itself), and test the checker
   against the *live* registry.
3. **Dead routing data — parts of the contract are unenforced (major; C32, C25).**
   `task_kind_floors` and `binding.escalation` are computed and written to local config
   (routing.py:194–212, :952) but **no hook reads them** (auditor-verified: grep over
   `hooks/*.py` empty); `gate_triggers` counts were already found dead (C25 queued). The
   thesis "enforced, not documented" is fully realized only for the commit guard and the
   delegation nudge. Cheap fix: an advisory floor check in the delegation-log hook —
   `bound_model_for` already resolves the routed model at that exact point. Or honestly
   reclassify the fields as documentation.
4. **V1 rename in flight with incomplete propagation (raised priority; V1).** Worse than
   "not started": mixed naming already produces user-visible breakage — the consumer
   memory index links `akmon-*` names while files on disk are `keystone-*`
   (`_aitna/memory/README.md:23,25` broken), `README.md:52,54` link `develop/` where the
   dir is `meta/`, ROADMAP.md:21 says "Two roles" vs five, `KEYSTONE_*` env vars
   (hook_core.py:467,478), 77 keystone-remnant lines across 26 files (exact count).
   Every interim doc edit propagates remnants.
5. **Coverage-map marker convention silently degrades (moderate; C33).** `parse_zone`
   (routing.py:1043–1058) requires the literal `[zone:` prefix; the syntax is documented
   only in dev-meta docs and docstrings — not in MODEL.md, pipelines, role docs, k-*
   briefs, or the status line. Observed live in this audit: unbracketed `zone:X`
   descriptions → all five zones "uncovered", map hand-assembled. A silently degrading
   coverage map defeats the uncovered-seam mechanism the gate architecture leans on.
6. **Role docs partially restate the role→kinds matrix (moderate; C34).** Registry is
   the declared single owner, yet review.md:57–59 names 2 of its 4 kinds, architect.md:66–68
   3 of 6, engineer.md:54–55 4 of 10. Partial duplication is drift primed to happen:
   go link-only, or generate the lines from the registry.
7. **USE-surface leak (design defect; C35).** `skills/stats-digest/SKILL.md:11` links
   `../../meta/design/model-routing.md` — a consumer-facing skill citing the dev tree,
   violating ADR 0003's own cordon (verify errors on exactly this). `skills/release/`
   is the same surface and was checked by no zone — sweep it too.
8. **Tool-layer LLM-agnosticism is design-true, operations-false (A9).** Agnostic data
   layer (semantic policies, no model names committed); vendor-coupled tool layer:
   `.claude/` paths baked in (routing.py:28–30, stats.py), Anthropic-only usage API
   (stats.py:32), Claude transcript/`agent-*.jsonl` assumptions, inconsistent vendor
   defaults (init: anthropic; second_opinion.py:73: openai), report_dir vendor-flip,
   Codex runtime ask/deny enforcement untested (C28b), **Gemini absent from the registry**
   despite the GEMINI.md pointer.
9. **Hook runtime fragilities (minor; C36).** Commit-guard regex stops at `|&;` but not
   `$(git push)` (C1 deferred, unchanged); `/tmp` markers race and outlive sessions
   (stale-counter false fires on session-id reuse); `model-routing.py` `main()` and
   malformed-transcript fallback untested; delegation-log write path untested.
10. **k-validator had zero recorded uses** until this audit's evidence run (log:
    k-mechanic 8 · k-explorer 6 · k-auditor 4 · k-implementer 2 · k-synthesizer 1 ·
    k-validator 0→1). Design-imbalance signal to watch, not a defect.

## 3. Isolation / abstraction / subagent economics — assessment

The strongest part of the project; decisions hold up:

- **Isolation by construction:** clean-context auditor (gate-pack-only input), capability
  enforcement by *tool set* rather than prompt trust, gitignored generated k-* defs whose
  `model:` frontmatter follows the local orchestrator. Matches host-harness prior art and
  exceeds it in task-kind granularity and cross-model tiering.
- **Abstraction as data:** tier vocabulary + finite task-kind matrix in the registry,
  semantic selection policy instead of model names, the leverage principle concentrating
  the maximal model at three low-token points (plan draft on signal, pre-fan-out plan
  check, whole-gate audit). Rejected-branch registers and the ADR trail are exemplary.
- **Economics, observed in this audit:** the 5-zone haiku fan-out absorbed the reading
  (~337k subagent tokens, session telemetry — unverified by the auditor) while the
  orchestrator window stayed lean. Worker weakness appeared exactly where the design's
  own session-mining predicted — calibration and fix-direction (zone R framing; the
  validator's wrong registry-fix suggestion) — and was caught by the upper rungs both
  times. The escalation contract works as designed.

## 4. Subagents ↔ roles ↔ pipelines

Coherent on paper and mostly in code: tier lines at the right steps, audit anchors and
bounded loop-backs present in operative docs, cross-cutting verification kinds exempt
from role gating (A7(b)/C18). Open: the C16–C20 wave awaits D2; the deterministic
gate-runner (C24) is queued, so pack-assembly is code but gate entry remains judgment —
the D4 "maximally code" bar is not yet met at the gate seam; findings 3 and 5 weaken the
enforcement half of the binding.

## 5. Consumer attachment — alphavar

Attach contract holds: AGENTS.md akmon block + @-imported guardrails, `.akmon.toml`
(v0.2.1, pinned runner), `sync.py --check` clean, all three charters conform
(inherit-not-restate), `.gitignore` complete for per-user artifacts, CI wired to run both
contract checks. Red `verify --strict` is fully explained by finding 2 plus finding 4's
memory half-rename — "local mid-migration state" is the parsimonious reading (remote CI
history not checkable here; no bypass hypothesis needed).

## 6. Bottlenecks

1. **Owner-verification (D2) queue** — ~9 pending / 1 verified; C24/C25/V1 stand behind
   it. Owner attention is named the second budget and is measurable (C13/C19), but
   throughput < inflow. Recommendation: batch-verify the C16→C17→C18→C20 chain (one
   design lineage); consider priority lanes in the ledger.
2. **Context window** — pressure bands, isolation-by-delegation and zero-token logging
   are in place; the gap is axis-2 (C29, approved not built): axis-1 counts calls, so a
   thousand-line inline diff is free until the count trips. Highest-leverage next
   mechanism for window utilization.
3. **Multi-model / multi-vendor** — ladder + dynamic reasoner + pinned-max auditor work
   on Anthropic; cross-vendor is finding 8 (A9). "LLM-agnostic" is currently a property
   of the data, not of operations.
4. **Bus factor 1** — the owner is sole verifier and committer by design (D2/D5); at
   more consumers this scales only via batching and moving checks into code.
