The owner authorized the header-optional A qualification under seal `adccd64a2c30828359a6b76e9164b15fd2744c6a481cb39cd7d75cc28590abd6`. Its first `advance` made no model call or reservation: Codex quota telemetry returned `401 token_expired`. The ledger has its header only, but the runner left a private directory for the first call. The [Codex review](../../reviews/a22-p3-v3-qualification-startup-resume-review.md) records the code path and evidence.

## Decision requested

**Recommend narrow same-seal pre-dispatch reconciliation.** Treat this particular authentication failure as an unmet prerequisite before the first scheduled call, not as a retry or replacement of a model call. Keep the accepted 32-cell schedule, prompts, scorer rules, 128 one-call slots, models, account binding, token ceiling, and quota thresholds unchanged. Make no change to any sealed input or to the ledger header. This decision does not authorize B/C or any additional call.

The runner copies credentials from the separate private `AUTH_SOURCE` at `/tmp/a22-p3-v3-successor-9xViiq/codex-home-run/auth.json`. The main Codex credential is valid for the same sealed account. The old source bytes have been preserved in a private backup, and `AUTH_SOURCE` has been refreshed from that main credential. A read-only quota RPC on a fresh copy of the refreshed source returned interpretable usage of 4% five-hour and 9% weekly; no model call was made. The operator should now perform these checks and one reconciliation in the isolated checkout:

1. Verify the existing seal, approval, and ledger header; confirm there is no reservation/completion event, `prepared.json`, dispatch artifact, provider output, or result for the first call. Inventory and hash every file in the first call directory, including Codex home SQLite and skill files and any state from the read-only stale-credential diagnostic; classify each as local pre-dispatch state and stop on anything unexpected. Keep credential bytes private.
2. Move the complete orphan first-call directory atomically to a unique private `pre-dispatch-stops/` path in the same runtime. Do not delete or overwrite it. Record the source and destination names, hashes, classification, and the unchanged ledger hash in a private reconciliation record and a metadata-only review. A second orphan or any ambiguous evidence stops the procedure.
3. Recheck the refreshed `AUTH_SOURCE` account ID against the seal and run a new read-only `account/rateLimits/read` using the pinned Codex CLI and a fresh private copy of that source. Require interpretable limits below 80% five-hour and 90% weekly. Then run exactly one `advance`; its own fresh quota gate remains authoritative. Continue sequential one-call slots only while the accepted protocol's stops and V3-only 5,000,000-token ceiling permit. A provider reservation, dispatch, terminal failure, account mismatch, or ambiguous usage is never reconciled this way.

The reconciliation is a **one-time exception for this pre-reservation authentication stop**, since the accepted proposal did not define that state. It preserves the abandoned local artifacts and makes the first actual model request auditable under the existing seal. It should be accepted explicitly before moving the directory. The existing qualification approval then covers subsequent calls under the unchanged seal; per-call owner confirmations are unnecessary.

**Alternative:** declare this seal stopped and prepare a fresh successor with a new runtime, seal, approval, and a runner that records pre-reservation failures without occupying the scheduled evidence path. This has cleaner protocol semantics but adds another preparation cycle without increasing experimental information; no model calls have been spent in the current qualification.

No threshold or 5,000,000-token accounting relaxation is proposed. Those were not the cause of the stop. The goal is to remove an avoidable startup state ambiguity and then spend the already approved experiment budget on the A grid.
