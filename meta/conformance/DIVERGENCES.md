# Divergence register

Where the JavaScript implementation differs from the Python one **on purpose**
([ADR 0020 D08](../decisions/0020-node-consumers-js-implementation.md)). The port is native: it keeps
the platform's own behavior where the runtime's standard differs from Python's, and it never
differs in product behavior — a hook decision, the bytes of a written file, a `verify` finding, a
`check` result, or the text an owner reads in normal use.

A difference not listed here and not fixed is a defect. The differential run (ADR 0020 D03) ends
every finding in one of the two: a fix in the implementation that is wrong, or a row below.

| Id | Area | Python | JavaScript | Why accepted | Who sees it |
|---|---|---|---|---|---|
| DV1 | `codex-hook -h` / `--help` | argparse prints the usage block and exits 0 | every argument error, help included, is a one-line crash and exit 1 | a hook has no reader for a usage block; owner decision 2026-10-11 ("native port") | someone running a hook by hand |
| DV2 | JSON numbers in a hook payload and in transcript lines | `1.0` stays a float, an integer is exact at any size | `JSON.parse`: `1.0` reads as `1`, an integer beyond 2**53 is inexact | a payload field is only tested for type and truthiness or spelled into a marker file name; the one visible case is a `delegation-log` `description` of `1.0` (Python logs `1.0`, JS `1`). Registry, overlay and config files keep their float spelling (`FloatValue`) | nobody in normal use; owner decision 2026-10-11 |
| DV3 | Non-finite literals | `NaN`, `Infinity` accepted by `json.loads` in settings, overlay and transcript files | `JSON.parse` refuses them; payloads are scanned by `pyjson.mjs` and match Python | the standard JSON grammar is the runtime's; those files are written by tools that never emit them | a hand-edited file |
| DV4 | stdin | under a C/POSIX locale Python reads with `surrogateescape` (an invalid byte survives); a closed descriptor 0 is `AttributeError` | always strict UTF-8; a closed descriptor 0 is reopened by node on `/dev/null` and reads as an empty payload | the locale mechanism is Python's | a harness feeding invalid bytes |
| DV5 | Time zone | libc | with `TZ` set the offset is asked of `date` (23 spellings match); with `TZ` unset `Date` answers | ICU and libc disagree on POSIX-style zones; the offset is what the log line spells | a delegation-log timestamp's offset |
| DV6 | Emptied shipped data file (agents or gate data with missing keys) | `KeyError` | `TypeError` | the class name is a stack-trace detail of a broken carrier; the crash line is the same one line with another class | a corrupted install |
| DV7 | Off-contract calls | `HookResult` rejects a missing event name or an unknown field (`TypeError`); `git_commit_guard_result(branch=[])` is an `ask` | `HookResult` accepts both; a non-string branch is not a branch | the Python signature is a typed contract, not a decision; callers are the hooks | a caller of the module API |
| DV8 | `markers` errors | a lone surrogate in an identity: `UnicodeEncodeError`; an unknown kind: `KeyError` with `repr(key)` | the same classes are thrown (`pyError`), but the message of an unknown kind quotes with JSON, not `repr` | the unit table pins that both raise; only a `node:test` covers the surrogate | a corrupted install |
| DV9 | Filesystem permissions | `Path.is_dir()` / `is_file()` raise on `EACCES` (Python 3.11–3.13) | `materialization` answers false; `routing` follows Python | Node's `statSync` has no such split; only Python 3.12.3 was available to check | a project directory the user cannot read |
| DV10 | `harnessCommand` | `{harness!r}` quoting of an unknown name | `'…'` quoting; the table is a plain object | message text of an error for a name no table holds | a mistyped harness name |
| DV11 | Detail of a broken record or config file (`RecordError` text in `check` and in `verify`'s `check.config`, the parse error inside a finding) | the sentence of `tomllib` (`Invalid value (at line 1, column 9)`) | the sentence of the vendored smol-toml (`parse failed at line 1, column 9: invalid value`); a duplicate key, a BOM and invalid UTF-8 differ the same way | each implementation names its own parser's words; the corpus pins that the file failed and which (`{{parse-error}}`), not the words | an owner fixing a hand-edited record |
| DV12 | Command-line parsing (`akmon`, `check`, `sync`, `verify`) | argparse: a `usage:` line, abbreviations (`--chan`), `-h` text from argparse, `command, args` as the missing names | `node:util` `parseArgs`: one `akmon <command>: error: …` line, no abbreviations, a short usage text, `required: command` | the platform's own parser (D08); the exit code (2) and the stream (stderr) are the same | someone mistyping a flag |
| DV13 | `akmon hook <name>.<suffix>` | accepts `<name>` and `<name>.py` | accepts `<name>` and `<name>.mjs` (`role-on-code.py` is an unknown hook) | the suffix is the language's | someone running a hook by hand |
| DV14 | A check table that fails validation after other checks | the invalid entry raises at that check; later checks never run | every check has run when the invalid one is found; exit 1 and an empty stdout are the same | `runChecks` is a straight port; nothing observable differs in output | nobody |
| DV15 | Integers beyond 2**53 in `.claude/settings.json` (user-owned content `sync` merges) | written back unchanged | refused as a plan error (exit 2): `json_writer` has no big-integer form and a silent rounding would rewrite the owner's file | a lossy rewrite of a hand-owned file is worse than a refusal | a settings file holding such a number |
| DV16 | Uncaught crash text of `sync` and `verify` (a directory where a `SKILL.md` or guardrail copy belongs, a non-UTF-8 stub, `TASKS.md`, `SKILL.md` or `.codex/hooks.json`) | the Python traceback | Node's stack trace; exit 1 on both | a traceback is the runtime's own | someone with a corrupted tree |
| DV17 | Wording of `invalid JSON: …` for a broken settings file | CPython's `json` sentence; 3.13 and 3.14 word two cases differently from 3.11/3.12 | follows CPython 3.11/3.12.3 (checked on 25,000 fuzzed documents) | the corpus normalizes the parser words (`{{parse-error}}`); 3.13/3.14 were not available to check | a hand-edited settings file |
| DV18 | A project switching ecosystems with one Python-spelled akmon command beside a user command in one settings entry | the wanted entry is skipped when its command string equals the existing one | the Node spelling is a different string, so the entry is added | only arises when the ecosystem changes; the output is otherwise identical | a project moving from the Python to the Node attach |
| DV19 | Integers beyond 2**53 in the model-routing registry or overlay `verify` reads | exact | read as the nearest number (`readJson(…, {lossy: true})`) | `verify` only validates these files and writes nothing; the findings are the same (checked in the differential) | nobody |
| DV20 | An `@~user/…` import in `AGENTS.md` (always-loaded population) | `Path.expanduser` asks the system's user database (NSS: LDAP, SSSD, …) | reads `/etc/passwd`; `@~/…` uses `$HOME`, else `os.userInfo()` | Node has no NSS lookup; a home directory import in a committed file is already outside the project | a user known only to a directory service |
| DV21 | A selected file outside the project root (`always_loaded.populations`) | `ValueError` whose text is 3.11's or 3.12's `relative_to` sentence | `ValueError` with the 3.12 sentence | the class is the contract (the unit table pins it); the sentence is the interpreter's | a caller of the module API |
| DV22 | `.codex/hooks.json` with an integer-like event key (`{"hooks": {"B": …, "1": …}}`) | events visited in insertion order | integer-like keys first (JavaScript object order) | only which unmapped event an error names can differ; generated wiring has no such key | a hand-edited wiring file |
| DV23 | Nesting depth of a `hooks/list` response | `RecursionError` at CPython's depth (3.11 and 3.12 differ) | `pyjson.mjs`'s depth, not pinned against either | a refused response is a protocol failure either way, reported as the same `codex.host-trust` warning; no table row pins the depth | nobody in normal use |
