# Measurements — harness and vendor facts, as measured

Project memory for facts akmon relies on but does not control: how Claude Code, Codex and the
vendor APIs behave. **What belongs here:** a fact that does not follow quickly and plainly from
the vendor's documentation, so establishing it took an experiment — a live probe, a replay of
transcripts or logs, or a reading of the shipped binary or vendor source. **Not a retelling of
vendor documentation:** a fact the docs state plainly is cited from the docs where it is used,
not copied here; a documented fact earns a row only when an experiment confirmed it on a
version, contradicted it or made it sharper, and the row then records that experiment. **Grep
here before a probe**; if a row covers the question at the version in use, cite it instead of
measuring again. **After a new measurement, add a row.**

A row names the version it was measured on and covers later releases of the same harness
under semver. Claude Code and codex-cli number their releases as semver: a patch release is a
fix and does not change the integration points akmon relies on — hook events and payloads,
instruction loading, CLI flags — and a minor release is compatible in the same points by that
notation. A patch or minor bump is therefore **not** a reason to re-measure: cite the row with
both versions named, and re-check only in passing — when a probe runs anyway, or when an
observation contradicts the row. A major bump or an observed contradiction makes the row a
candidate for re-verification: re-check it, then either append the new version to the row
(result unchanged) or add a new row and mark the old one `superseded by M<n>` (result changed).
The residual risk of a breaking change inside a minor line is accepted rather than paid for in
routine re-probes; a deliberate sweep across accumulated minor releases is tracked as N9.
A measured row is never deleted. The ids M4–M7, M10 and M11 were retired when this file
stopped holding documentation readings — their sources stay in the
[C80 evidence](reviews/c80-context-fill.md) — and a retired id is not reused.

**Row format** — one line per fact, so a grep returns the whole record:

`- M<n> · <fact, with the searchable names in it> · <harness/vendor + version> · <date> · <method> · evidence: <link> · used by: <task/D2 ids>`

**Method** says how the fact was established: `probe` (a live harness run), `replay` (existing
transcripts or logs read back), `source` (the shipped binary or the vendor source code read).
Relative links resolve from `meta/`. Owned by C82.

A behavioural trial on a model is recorded the same way: the row names the model and the harness version, and gives its numbers per model so a later run on another model or vendor compares row to row; the design and scoring live in the linked evidence.
